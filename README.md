# Growth Engine ERP

A web ERP for a trading business: dashboard, masters (items, units, categories, brands,
warehouses, suppliers, customers), and later purchase, sales and stock.

Status: the dashboard and the master forms work in the browser. The PHP backend and the MySQL
schema for the masters are written but **have not been run against a real database yet**:
expect small fixes the first time you run them.

## Stack

No frameworks and no build step. Each layer is plain and small on purpose.

| Layer | What | Where |
|---|---|---|
| Web server | Caddy 2: HTTPS, security headers, one origin for everything | `Caddyfile` |
| Frontend | Static HTML + vanilla JavaScript + CSS, hash router (`#/masters/item/new`) | `frontend/` |
| API | Plain PHP 8.2+ JSON endpoints, one file per resource | `backend/public/api/*.php` |
| Business logic | One PHP module per master: validation and SQL | `backend/src/*.php` |
| Database | MySQL 8 / MariaDB 10.6+ through PDO, InnoDB, utf8mb4 | `backend/migrations/*.sql` |
| Tools | CLI scripts run with `php` | `backend/bin/` |

### How a request flows

```
browser ──► Caddy ──► file exists in frontend/?  ──► served as a static file
                  └─► otherwise ──► PHP-FPM, document root backend/public/
                                     /api/items.php
                                       requires src/api_bootstrap.php   (JSON headers, session, CSRF, errors)
                                       requires src/items.php           (rules + SQL)
                                         uses db.php → PDO → MySQL
```

`backend/src`, `backend/storage` (uploaded files) and `backend/.env` sit outside both web roots,
so they can never be downloaded.

## The database

**The source of truth is `database model/Growth-Engine-Masters-HD (1).png`**: 19 tables and every
foreign key between them. `backend/migrations/2026_11_05_001_masters.sql` creates exactly that.

Conventions:

- Table and column names are `snake_case` and match the diagram.
- Every id is `INT UNSIGNED AUTO_INCREMENT`; foreign keys are real `FOREIGN KEY` constraints.
- `ENGINE=InnoDB`, `utf8mb4_unicode_ci`.
- Codes such as `ITM-2026-0001` are generated by the server (`next_code()` in `src/master_validation.php`), never typed by users.
- **Never edit a migration that has already run.** Add a new dated file (`2026_11_20_001_add_x.sql`); `php backend/bin/migrate.php` applies the new ones and records them in `schema_migrations`.
- Statements in a migration end with `;` at the end of a line (that is how `migrate.php` splits them).

Every foreign key in the diagram is a **lookup popup** in the UI ("Select UOM", "Select Warehouse" …).
The popup loads its list from the matching endpoint (`api/uoms.php`, `api/warehouses.php` …), and the
form sends the chosen id (`uomId`, `warehouseId` …). Adding a new foreign key means: a column + FK in a
migration, a list endpoint, and a `data-lookup` field on the form (see `LOOKUPS` in `dashboard.js`).

Form fields that have no column in the data model yet, and are accepted but not stored:
item batch expiry and PDF spec link; contact designation and email; document type and expiry;
the Quotations and Previous Purchases tabs; brand and category descriptions.

## The API contract

- Success: `{ "data": … }`. Failure: `{ "error": "message", "fields": { "payloadKey": "message" } }` with 4xx/5xx.
- `422` = validation (the form highlights the fields named in `fields`), `404` not found, `409` duplicate, `500` logged server-side.
- Writes need the `X-CSRF-Token` header; the page gets it from `GET /api/session.php`.
- There is **no login yet**. `current_user()` in `backend/src/security.php` is where it goes; the `users` table already exists.

The full endpoint list is in [backend/README.md](backend/README.md).

## Running it locally

Needs PHP 8.2+ with `pdo_mysql` and `mbstring`, PHP-FPM, MySQL 8 or MariaDB 10.6+, and Caddy 2.
Step by step: [backend/README.md](backend/README.md#run-it-locally). In short:

```sh
cp backend/.env.example backend/.env      # database name, user, password, port
php backend/bin/migrate.php                # create the tables
php backend/bin/seed-demo-data.php         # optional demo masters
# start PHP-FPM on 127.0.0.1:9000, then:
APP_ROOT=$PWD caddy run --config Caddyfile # https://localhost
```

The frontend alone (no saving, empty popups) also opens with `python3 -m http.server` inside `frontend/`.
